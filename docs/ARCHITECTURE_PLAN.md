# 《猫猫背包守夜》商业级架构方案

结论：本项目推荐使用 **Cocos Creator 3.8 LTS/3.x + TypeScript + 微信小游戏发布**。

不推荐第一版继续用纯原生 Canvas 手写引擎。纯 Canvas 可以做 Demo，但商业级项目会在 UI 编辑、动画、资源管理、适配、性能调优、团队交接上成本过高。

## 1. 为什么不用 Unity

Unity 优点：

- 生态大，3D/复杂动画强。
- C# 对 Java 工程师更友好。
- 大项目能力强。

但对当前项目不优先：

- 你的游戏是竖屏 2D 微信小游戏，Unity/团结引擎整体偏重。
- 包体、启动速度、微信小游戏适配链路更复杂。
- UI 是大量 2D 面板、卡片、列表、按钮、弹窗，Cocos 更轻。
- 希望 AI 自主完成时，Cocos 的 TypeScript 文件、Prefab、配置表更容易被 Codex 批量生成和维护。

## 2. 为什么不用纯 Canvas

纯 Canvas 优点：

- 最轻。
- 无引擎依赖。
- 可以直接运行在微信小游戏。

但商业级风险：

- 所有 UI 布局、点击检测、动画、资源加载、适配都要自己写。
- 后续页面多，背包、宠物、商店、任务、邮件、天赋树会迅速复杂。
- 缺少编辑器可视化，设计还原和运营迭代会慢。
- 对新人不友好，也不利于多 Agent 分工。

## 3. 推荐架构

技术栈：

- 引擎：Cocos Creator 3.8 LTS/3.x
- 语言：TypeScript
- 目标平台：微信小游戏
- 渲染：Cocos 2D UI + Sprite + Spine/序列帧可选
- 数据：本地存档 + 后续微信云开发/自建后端
- 配置：JSON 表驱动
- 资源：Bundle 分包 + 图集 + 压缩纹理

## 4. 核心分层

### 4.1 Core 层

负责项目基础能力：

- `EventBus`：模块通信。
- `SceneRouter`：场景跳转。
- `ResourceManager`：资源加载和释放。
- `AudioManager`：音乐音效。
- `TimeManager`：倒计时和每日刷新。
- `SaveManager`：本地存档。

### 4.2 Data 层

负责数据和配置：

- 玩家存档：等级、经验、金币、钻石、体力。
- 背包：武器、道具、宝箱。
- 宠物：等级、星级、出战状态。
- 任务：每日任务、成就。
- 配置表：武器表、宠物表、关卡表、怪物表、商店表、天赋表、技能表。

### 4.3 Game 层

负责纯玩法逻辑：

- 战斗系统：波次、怪物、攻击、伤害、胜负。
- 武器系统：冷却、攻击轨迹、合成、升级。
- 宠物系统：属性加成、技能效果。
- 技能系统：局内三选一、刷新。
- 商店系统：购买、刷新、广告免费。
- 任务成就系统：事件驱动进度。

### 4.4 UI 层

负责界面和交互：

- 通用组件：按钮、标签、卡片、进度条、弹窗、红点。
- 页面面板：背包、商店、宠物、成就、邮件、设置、任务、天赋。
- 动效：按钮按下、领取奖励、合成成功、胜利结算。

### 4.5 Service 层

负责平台能力：

- 微信登录。
- 微信广告。
- 分享。
- 排行榜开放数据域。
- 云存档或服务端 API。
- 支付/虚拟支付合规预留。

## 5. 多 Agent 分工调整

推荐 7 个 Agent：

| Agent | 职责 |
| --- | --- |
| ProductAgent | 产品规则、MVP 范围、商业化闭环 |
| UIUXAgent | UI 还原、交互规范、Prefab 结构 |
| AssetAgent | 切图、图集、资源压缩、Bundle |
| ClientArchAgent | Cocos 项目架构、基础框架、场景路由 |
| GameLogicAgent | 战斗、背包、合成、宠物、任务、商店 |
| PlatformAgent | 微信登录、广告、分享、存档、排行榜、合规 |
| QAReleaseAgent | 自动测试、性能检查、包体、上线清单 |

执行顺序：

1. ProductAgent：确定 MVP 和商业级验收标准。
2. UIUXAgent：把设计图转成组件规范和 Prefab 清单。
3. AssetAgent：整理资源、切图、图集和 Bundle 方案。
4. ClientArchAgent：创建 Cocos 项目骨架和基础框架。
5. GameLogicAgent：实现玩法系统。
6. PlatformAgent：接微信能力和广告能力。
7. QAReleaseAgent：验收、修复、生成上线清单。

## 6. 对设计图的合理修改建议

你的设计图方向很好，但商业上线需要做这些调整：

- 底部导航在不同页面中保持完全一致，避免有的页面是关闭按钮、有的是返回按钮、有的是底部 tab，规则要统一。
- 战斗页底部武器槽较大，低端机上要确保不会遮挡核心战斗区域。
- 部分页面文字很大，中文长文本需要动态缩放或两行显示。
- 邮件页左右双栏在窄屏上可能拥挤，移动端建议改成列表优先，点击后进入详情抽屉或弹层。
- 天赋树节点很多，需要支持滚动或缩放，不要固定塞满一屏。
- 宠物页和宠物详情页功能重复，建议合并成一个主宠物页，详情用弹窗或右侧详情面板。
- 登录页协议勾选、适龄提示、隐私政策入口必须保留。
- 广告刷新、双倍领取、体力消耗要提前预留微信广告失败、取消、无广告可看等状态。

## 7. 商业级上线标准

### 7.1 可玩标准

- 10 分钟新手体验闭环。
- 登录、主页面、战斗、背包、商店、宠物、任务、成就、邮件、设置全部可用。
- 战斗失败和胜利都有结算。
- 货币、奖励、消耗不会出现负数或重复领取。
- 新手引导至少覆盖：开始战斗、合成、升级宠物、领取任务。

### 7.2 技术标准

- 微信开发者工具可构建。
- 真机低端设备可运行。
- 首包大小可控，资源使用分包/远程加载。
- 关键资源使用图集，避免大量小图请求。
- 页面切换无明显卡顿。
- 存档可恢复，异常退出不丢关键数据。

### 7.3 运营标准

- 配置表可调，不需要改代码就能改商品、任务、奖励、关卡。
- 红点系统统一。
- 邮件系统可发补偿。
- 活动入口可预留。
- 广告点位可开关。

### 7.4 合规标准

- 用户协议、隐私政策入口。
- 适龄提示。
- 健康游戏提示。
- 广告激励不误导。
- 若接入付费，必须按微信小游戏和平台政策处理。

## 8. 第一阶段交付目标

第一阶段不追求所有细节完美，先做“商业级骨架 + 可玩 MVP”：

- Cocos Creator 项目可打开。
- 主要场景和 Prefab 结构搭好。
- 使用设计图风格复刻主要 UI。
- 战斗能自动跑完一局。
- 背包合成、宠物升级、商店购买、任务领奖可用。
- 数据配置表驱动。
- 微信小游戏可预览。

第二阶段再做：

- 精细切图。
- 图集压缩。
- 新手引导。
- 广告接入。
- 排行榜。
- 性能优化。
- 真机适配。
- 上线材料。
