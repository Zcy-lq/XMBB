# Asset Visual Acceptance

日期：2026-05-24  
负责阶段：`visual_compare` 准备阶段  
适用批次：`assets/configs/asset_generation_batch_p0.json`

## 目标

本文件定义 P0 runtime 素材进入 `visual_compare`、`asset_audit` 和后续 `promote_or_reject` 时的商业级视觉验收标准。目标不是像素级复刻参考图，而是让素材在微信小游戏竖屏实机环境中足够清晰、完整、可复用，并能支撑“夜晚战斗、获得奖励、升级合成背包物品、培养宠物和天赋、推进更高波次”的核心玩法。

参考图可以被专业修正：允许优化构图、明暗、色彩、材质、比例、可读性和商业化完成度；不允许改变核心玩法语义，不允许把独立素材做成整页 UI 截图，不允许把战斗、背包、商店等页面功能关系改成另一种游戏。

## 全局硬性规则

1. 正式 runtime 素材只能从通过审核的候选 PNG 晋升到 `assets/textures/runtime`，不能从 `tmp/`、`assets/textures/references/`、`temp/`、`library/` 或备份目录引用。
2. 测试图、QA 截图、接触表、整页参考图、浏览器截图、Cocos 预览截图都不能当正式素材，也不能被裁切后伪装成正式素材。
3. 单体素材必须独立表达自己的用途：按钮是按钮底板，图标是图标，怪物是单个战斗精灵，特效是可叠加效果，背景是不带 UI 和角色的场景。
4. 所有透明素材必须有干净 alpha、透明角、无脏边、无测试底色、无水印、无文字、无 mockup 边框。
5. 所有素材必须符合 P0 批次声明的尺寸、透明度、九宫格开关、候选路径和输出路径；视觉通过不能替代配置通过。
6. 商业级标准优先于参考图缺陷：若参考图存在糊、裁切、拥挤、误导性 UI 或不可复用元素，AssetAgent 可专业修正，但需保留玩法语义并在 QA 或设计文档记录偏差。
7. 竖屏 720x1280 使用场景下，素材不得导致按钮文字不可读、背包格子误触、战斗角色难辨、特效遮挡关键状态或背景抢夺前景注意力。

## P0 类别验收标准

### 按钮

适用：`rt_btn_icon_round`、`rt_btn_red`，并参考现有 `btn_yellow`、`btn_green`、`btn_blue`、`btn_brown` 家族。

通过标准：

- 按钮底板无内置文字、无图标、无状态标签，中心区域可承载运行时文字或图标。
- `rt_btn_icon_round` 必须圆形居中，外圈、内面和高光层级清楚，缩到 48-64px 仍能看出可点击感。
- `rt_btn_red` 必须是危险/取消语义的暖红色按钮，和现有按钮家族共享手绘、木质/金边、柔和高光的风格。
- 九宫格按钮的四角、边框、高光和投影不得落入主要拉伸区；横向拉伸后不能出现边框断裂、纹理重复脏线或中心鼓包。
- 与夜晚森林、羊皮纸、木质 UI 同屏时有足够对比，但不能像系统原生按钮或现代扁平广告按钮。

拒绝标准：

- 从整页截图里裁切出的按钮。
- 按钮上带“购买”“取消”“返回”等烘焙文字。
- 红按钮像血腥警告图、真实金属工业按钮，或与可爱猫背包幻想风格脱节。

### 九宫格

适用：`rt_panel_dark_glass`、`rt_panel_parchment_card`、`rt_btn_red`，并影响 `panel_dark`、`panel_parchment`、`panel_wood_header` 等同族素材。

通过标准：

- 九宫格素材必须有明确不可拉伸角区、可平铺/拉伸边区和干净中心区。
- `rt_panel_dark_glass` 必须表现深色半透明玻璃信息面板，适合主页或战斗信息承载；中心不能有复杂纹理抢文字。
- `rt_panel_parchment_card` 必须表现独立商品/物品卡片，不应看起来像大背景板；适合放置图标、价格、数量、状态角标。
- 透明区域边缘必须抗锯齿干净，缩放后不能出现白边、黑边、方形底色或半透明脏块。
- 在 720x1280 竖屏中，面板需要能承载中文 UI 文本，背景明暗不得让白字/深色字失去可读性。

拒绝标准：

- 带完整页面布局、列表、按钮、角色或标题栏的整页图。
- 中心已经画死文字框、插画或装饰导致不能复用。
- 九宫格拉伸后角被拉宽、边框厚度不一致、纹理明显重复。

### 图标

适用：`rt_icon_paw`、`rt_icon_nav_backpack`、`rt_item_weapon_fishbone_bow`。

通过标准：

- 图标必须透明背景、主体居中、轮廓清晰，64px 可读；底部导航图标需在 48px 仍能识别。
- `rt_icon_paw` 是通用猫爪主题图标，不是货币；不能像金币、奖章、代币或红点奖励。
- `rt_icon_nav_backpack` 必须一眼看出是背包/行囊，并和商店、战斗、天赋、宠物导航图标形成同一套底部导航语言。
- `rt_item_weapon_fishbone_bow` 必须明确是弓，不是矛、法杖、鱼骨装饰或普通木弓；45 度道具展示可以保留，但不能裁切弓弦。
- 图标的材质、描边、阴影和光源方向应与现有 runtime 接触表中的商业候选素材统一。

拒绝标准：

- 图标包含文字、数字、等级、价格、按钮底板或整页 UI。
- 透明区域有测试背景、白底、黑底或生成残片。
- 关键语义混淆，例如猫爪像货币、背包像箱子、鱼骨弓像长矛。

### 战斗背景

适用：`rt_bg_battle_forest_safe`、`rt_bg_battle_prepare_safe`。

通过标准：

- 必须是 720x1280 竖屏不透明背景，适合独立前景角色、怪物、掉落物、伤害数字和 UI 叠加。
- `rt_bg_battle_forest_safe` 必须表现夜晚森林战斗场景，有清晰地面和前景战斗区域；不能烘焙主角、怪物、宝箱、伤害数字或按钮。
- `rt_bg_battle_prepare_safe` 必须表现战斗准备氛围，中心和下方有安全区承载准备面板、按钮和波次信息。
- 明暗层次要服务玩法：背景有夜晚幻想气氛，但前景角色和特效放上去后仍清晰。
- 允许参考图中的月光、营火、森林、路径等元素被重构得更专业，但不得把准备页和战斗页做成完整截图复制。

拒绝标准：

- 背景中已经画入角色、敌人、背包栏、顶部波次 UI、奖励宝箱或任何可交互 UI。
- 横版图强裁成竖版、关键主体被裁掉，或上下安全区无法承载 UI。
- 过暗、过花、过高对比导致战斗精灵和伤害数字不可读。

### 怪物

适用：`rt_monster_ghost`、`rt_monster_skeleton`、`rt_monster_goblin`。

通过标准：

- 每张图只能包含一个独立怪物精灵，透明背景，无地面、无 UI、无文字、无血条。
- 64px 可读，256px 下细节完整；轮廓、面部、武器或姿态能表达敌人类型。
- 风格是可爱幻想夜战敌人，危险感适中，不走恐怖、血腥或写实惊悚方向。
- 怪物之间必须有清晰差异：幽灵偏蓝白柔光和漂浮感，骷髅偏骨骼/小盾/轻甲，森林小敌人偏绿色、小体型、简单武器。
- 光源、描边、饱和度和比例应能与主角猫、战斗背景和特效同屏。

拒绝标准：

- 多个怪物合在一张图，或包含完整战斗截图。
- 怪物被背景、阴影、地台或装饰绑定，无法独立摆放。
- 过于写实、恐怖、暴力，或缩小后只剩模糊色块。

### 特效

适用：`rt_fx_bullet`、`rt_fx_hit`、`rt_fx_fire`。

通过标准：

- 必须透明背景，无文字、无 UI、无测试底色；边缘自然衰减，叠加在深色背景上清晰。
- `rt_fx_bullet` 需要有明确运动方向，尺寸和亮度不能遮住武器或敌人主体。
- `rt_fx_hit` 需要有清晰冲击中心和短促反馈感，适合命中瞬间，不应像永久徽章或道具图标。
- `rt_fx_fire` 需要是可复用火焰/暖光叠加素材，可用于营火或战斗反馈；不能绑定具体背景。
- 特效亮度可强调反馈，但不得长期遮挡血量、伤害数字、背包格子或点击目标。

拒绝标准：

- 特效带矩形黑底、白底、蓝幕或生成工具水印。
- 一张图包含完整序列帧、整页战斗画面或调试标签。
- 视觉语义不清，例如子弹像金币，命中特效像按钮，高光火焰像静态图标。

## Visual Compare 判定方式

1. 先看单图：尺寸、alpha、九宫格、主体语义、边缘质量、是否有文字/水印/截图痕迹。
2. 再看接触表：与现有 runtime 资产同屏时是否统一，是否有明显廉价感、风格断裂或缩略图不可读。
3. 再看 QA 截图：放入实际页面后是否改善商业观感，是否影响核心玩法信息读取。
4. 最后判定：`accept`、`revise`、`reject`。`accept` 才能进入晋升候选；`revise` 保留在候选目录并写明修改点；`reject` 不得进入 runtime。

## 记录要求

每个 P0 候选素材在视觉比较后至少记录：

- 素材 id、候选路径、目标 runtime 路径。
- 判定结果：`accept` / `revise` / `reject`。
- 关键原因：语义、商业完成度、alpha、九宫格、可读性、风格一致性。
- 如相对参考图有专业修正，说明修正点以及为什么不改变核心玩法。
- 使用的 QA 截图或接触表路径。注意这些路径只是证据，不是素材来源。
